# API

The service listens on `127.0.0.1:${SABER_PORT:-8100}`. There is no authentication; access is limited to localhost. Requests must carry a `Host` of `127.0.0.1`, `localhost` or `[::1]` (any port), or a name listed in the comma-separated environment variable `SABER_ALLOWED_HOSTS`; any other `Host` is refused with 403 to block DNS rebinding. Behind a TLS proxy, set `SABER_TRUSTED_PROXY_IPS` (comma list of single proxy addresses, no networks, empty by default). When the TCP peer is in that list, the `Origin` check uses the rightmost `X-Forwarded-Host` and `X-Forwarded-Proto` value, and both the direct `Host` and the forwarded host must be in the allowlist, so add the proxy upstream name to `SABER_ALLOWED_HOSTS`. The proxy must overwrite these headers rather than append (nginx: `proxy_set_header Host $host; proxy_set_header X-Forwarded-Host $host; proxy_set_header X-Forwarded-Proto $scheme;`). From any other peer those headers are ignored. The static frontend is served at `/`, and `GET /maps/{id}`, `GET /new`, `GET /vr`, `GET /vr/maps/{id}` and `GET /vr/beatsaver` answer with `index.html` so deep links and reloads work. Any other `GET /api/...` path answers 404 JSON `{"error"}`. All other responses are JSON.

## Routes

1. `GET /api/health`: `{"status": "ok"}`. Cheap liveness probe used by the container HEALTHCHECK; it does not read the library, write the store or call the analyser, and it sits behind the same `Host` check as every other route. At startup the first library refresh runs in a background thread, so `/api/maps` and `/api/maps/facets` list only the maps indexed so far until it ends.
1. `GET /api/maps?offset=0&limit=40&sort=title&order=asc&q=&status=all&env=&q_fields=`: one page of the library, refreshed first if the set of folders under `/levels` changed. Answers `{"items", "total", "offset", "limit"}`; `total` counts every map matching `q`, `status` and `env`. An original map is left out of the list, `total` and the facet counts while its fixed copy (the `<name> [saber-tooth]` folder Fix wrote) exists; `GET /api/maps/{id}` still returns it. Each item carries `fixed_copy_id` and `fixed_copy_folder` (on an original) and `original_id` and `original_folder` (on a fixed copy); all four are null otherwise.
   1. `sort` is one of `title` (default), `mapper`, `environment`, `status`, `errors`, `warnings`, `scanned_at`, `bpm`, `duration`, `levels`. `bpm`, `duration` and `levels` put maps without a value last in both orders. `levels` sorts by the highest difficulty present, then by how many are present. `status` sorts unreadable, error, warn, scanning, applying, fixing, queued, incomplete, unscanned, ok. `order` is `asc` or `desc`. Ties break by title, then id, so pages never overlap or skip.
   2. `q` is a case-insensitive substring of title, mapper, environment or folder (up to 200 characters). `q_fields` is a comma-separated list of `title` and `mapper` that restricts the text search to those fields (`q_fields=mapper` searches the mapper only). `status` filters to `all` (default) or a comma-separated list (also repeatable) of `error`, `warn`, `ok`, `incomplete`, `unscanned`, `unreadable`, `scanning`, `applying`, `fixing`, `queued`. `env` is an exact environment name, repeatable or comma-separated (up to 50 names); a map matches any listed value. Environment names must not contain commas; the web app always repeats `env`. `mapper` is an exact mapper name, repeatable (up to 50 names of 200 characters; commas are part of the name); a map matches any listed value. `level` is `Easy`, `Normal`, `Hard`, `Expert` or `ExpertPlus`, repeatable or comma-separated; a map matches when it has any selected level, or every selected level with `level_mode=all` (`any` is the default).
   3. `limit` is 1 to 100, `offset` is 0 or more. `duration_min` and `duration_max` (seconds, 0 to 7200) and `bpm_min` and `bpm_max` (0 to 1000) keep maps whose length or tempo lies within the bounds, inclusive; a set bound excludes maps without that value. Any bad value, including a minimum above its maximum, answers 400 `{"error"}`.
   4. Each item has `id`, `folder`, `title`, `mapper`, `environment`, `parse_error`, `errors`, `warnings`, `scanned_at`, `status`, `cover_url`, `difficulties`, `approved`, `pending`, `bpm`, `duration_s` and `job`. `bpm` is the Info.dat tempo; `duration_s` is the song length in seconds, from the Ogg audio file (sample rate and last granule position), else Info `audio.songDuration`, else the last note, bomb or wall converted with the tempo map; both are null when unknown. `job` is `{"id", "kind", "status"}` for the scan, apply or fix job queued or running for the map, else null. `approved` counts approved proposals not yet applied; `pending` counts proposals awaiting a decision. `status` is `unreadable` (parse error), `scanning`, `applying` or `fixing` (a scan, apply or fix job is running), `queued` (one is waiting), `incomplete` (never scanned and missing any of the five Standard difficulties), `unscanned` (never scanned, all five present), `error` (any error finding), `warn` (warnings only) or `ok` (scanned, no findings). Counts and `scanned_at` come from the last scan; `scanned_at` is null before one. `cover_url` is `/api/maps/{id}/cover` or null; `difficulties` lists the Standard difficulties in Info.dat. `audio_url` is `/api/maps/{id}/audio` or null when the map has no usable song file; `preview_start` is the Info preview start in seconds (v2 `_previewStartTime`, v4 `audio.previewStartTime`), or null when absent or when `audio_url` is null.
   5. `GET /api/maps/facets`: `{"status": {<status>: n}, "environments": [{"name", "count"}], "mappers": [{"name", "count"}], "levels": {"Easy": n, "Normal": n, "Hard": n, "Expert": n, "ExpertPlus": n}, "duration": {"min", "max"}, "bpm": {"min", "max"}, "total"}` over all maps, ignoring any filter. Environments and mappers sort by count descending, then name; maps with an empty mapper are not listed. Level counts are maps that have the level. `duration` (seconds) and `bpm` are the smallest and largest known value, or nulls when no map has one. Registered before `/api/maps/{id}`.
1. `GET /api/maps/{id}`: one item with the fields above, or 404.
1. `GET /api/maps/{id}/cover`: the cover image. The filename comes from Info.dat, must be a plain name ending `.png`, `.jpg` or `.jpeg`, must resolve to a regular file inside the map folder (no symlink out) and be at most 5 MB, else 404. Sends `Content-Type`, `Cache-Control: private, max-age=86400` and an `ETag` from modification time and size; `If-None-Match` answers 304.
1. `GET /api/maps/{id}/audio`: the map's song, streamed from disk. The filename comes from Info.dat (`_songFilename` or v4 `audio.songFilename`), must be a plain name ending `.egg`, `.ogg`, `.wav` or `.mp3`, and must resolve to a regular file inside the map folder (no symlink out), else 404; unreadable maps answer 404. `Content-Type` is `audio/ogg` (`.egg`, `.ogg`), `audio/wav` or `audio/mpeg`. Supports `Range: bytes=...` (206 with `Content-Range`; 416 with `Content-Range: bytes */size` for an unsatisfiable, inverted or malformed range) and sends `Accept-Ranges: bytes`, `Cache-Control: private, max-age=86400` and an `ETag` from modification time and size; `If-None-Match` answers 304.
1. `DELETE /api/maps/{id}`: permanently removes the map folder from `/levels` (it must be a real direct child folder, never a symlink), drops the map rows (scans, proposals, jobs) and refreshes the library. Answers `{"deleted": "<folder>"}`. 404 for an unknown map or a folder that is gone, 409 while the map has a queued or running job. There is no MCP tool for it.
1. `POST /api/maps/{id}/scan`: starts a `scan` job. Answers 409 if the map has a parse error.
1. `GET /api/maps/{id}/proposals`: proposals for a map, with before and after excerpts. Each proposal also carries `replaces` (the superseded proposal it replaced, else null) and `conflicts_with` (ids of other open proposals of the same difficulty that touch the same notes, by beat, position and colour, or lie inside a fill range). Approving overlapping proposals is fine: apply runs them in id order and re-checks the later one.
1. `POST /api/proposals/{id}/approve`: approve one proposal. Answers 409 for an applied or superseded proposal.
1. `POST /api/proposals/{id}/reject`: reject one proposal. Answers 409 for an applied or superseded proposal.
1. `POST /api/maps/{id}/approve-all`: approve every pending proposal for one map. Answers `{"approved": N}`.
1. `POST /api/maps/{id}/apply`: starts an `apply` job that writes the approved proposals into the sibling folder `<original name> [saber-tooth]`, or a numbered variant. Approved proposals apply in id order to an evolving map. A proposal whose notes an earlier one changed is re-checked: if its finding is gone it becomes `superseded` and is skipped; if the finding remains, a fresh `pending` proposal (`replaces` = the old id) is stored and the old one becomes `superseded`. The job result is `{"map_id", "folder", "applied", "superseded", "needs_review"}`, the three being proposal id lists (`needs_review` holds the new pending ids). The job fails only when applying leaves a new problem or a proposal has no finding to re-check.
1. `POST /api/maps/{id}/fix`: the one-click Fix. Returns `{"job": id}` and starts a `fix` job (map status `fixing`) that adds missing difficulties and fixes every finding it can, each fix verified against the map as earlier fixes left it, then writes the sibling folder `<original name> [saber-tooth]`; the original is never changed and the library is refreshed so the new folder appears. The beat analyser is used when reachable, else the fix runs without it (`analysed` is false). The job result is `{"map_id", "folder", "fixed_id", "analysed", "rounds", "applied", "before", "after", "difficulties", "complete", "errors", "unfixed"}`. `before` and `after` map difficulty, then `errors` or `warnings`, then rule to a count. `fixed_id` is the library id of the written folder. `folder` and `fixed_id` are null (and `after` equals `before`) when nothing needed fixing. `unfixed` lists the remaining findings, each with its `reason`. 404 for an unknown map, 409 when the map cannot be read. The MCP tool `fix_map(map_id)` starts the same job.
1. `GET /api/maps/{id}/timeline`: the crop timeline `{"map_id", "duration_s", "bpm", "hardest", "map_only", "grid_drift_s", "min_length_s", "nps", "sections", "lengths"}`. `nps` maps each difficulty that has notes to notes per second in 1 s steps. `sections` lists `{"start_beat", "end_beat", "start_s", "end_s", "nps", "intensity"}`. `lengths` has the keys `"60"` and `"120"`, each `{"enabled", "reason", "band", "suggestions", "starts"}`: `band` is the allowed length range in seconds, `suggestions` holds the best window then the next two (`{"start_beat", "end_beat", "start_s", "end_s", "length_s", "end_kind", "score"}`), `starts` is every allowed start with its allowed `ends` (`{"beat", "seconds", "kind"}`, kind `section`, `phrase`, `bar4` or `bar`). `min_length_s` is the shortest window the crop accepts (1.0). Suggestions, sections and allowed points are guidance only. `map_only` is true when the stored scan has no analysis. Times are given in beats and seconds. 404 for an unknown map, 409 when the map cannot be read, 422 with the reason when no Standard difficulty has notes or the song length is unknown.
1. `POST /api/maps/{id}/crop`: body `{"start_beat", "end_beat"}` or `{"start_s", "end_s"}`, exactly one pair (both or neither: 422 `send either start_beat and end_beat or start_s and end_s`); song seconds are converted to beats on the server with the map's own timing, BPM changes included, and the web UI sends seconds. Answers `{"job": id}` and starts a `crop` job that writes `<original> [label]` as a new folder (numbered when taken); any window is accepted with `start_beat >= 0`, `end_beat > start_beat`, the end inside the song and a length of at least 1 second (BPM changes included), with no section, snap-point or band requirement; the label is `1 min` or `2 min` when the length is within that band, else `crop MmSSs` (rounded seconds, e.g. `crop 3m00s`; a colon is not allowed in a Windows folder name); the original is never changed. 400 for a body that is not JSON, 404 for an unknown map, 409 when the map cannot be read or has a queued or running job (checked before the window), 422 naming the broken rule for a bad number or window. The job result carries `folder` and `cropped_id`. Optional body field `"replace": true` (a boolean, else 422; checked after the busy 409 and the window rules) saves the crop in place: the cropped map is written to a partial folder and read back, then the original folder (a real direct child of the levels folder, no symlink or junction) is renamed aside, the new folder takes its name and the old one is removed; any failed step restores the original and removes the partial. The map's scan, proposals and finished jobs are cleared, so it shows as not scanned, and the library is refreshed. The job result is then `{"map_id", "replaced": true, "folder": <original name>, "cropped_id": <same id>, "label", "start_beat", "end_beat", "length_s"}`. The MCP `crop_map` tool has no replace option.
1. `GET /api/maps/{id}/neighbors`: same query parameters as `GET /api/maps` (filters, `q`, `sort`, `order`; `offset` and `limit` are ignored). Answers `{"index": n, "total": t, "prev": {"id", "title", "folder"}, "next": {"id", "title", "folder"}}`, `index` 1-based in that list order. The list wraps: the first map's `prev` is the last, the last map's `next` is the first; a one-map list gives `prev` and `next` equal to the map itself. 400 for a bad filter, 404 for an unknown map or a map that is not in the filtered list.
1. `POST /api/generate`: body `{"url": "<youtube url>"}` or a multipart audio file in the field `file`. Starts one `generate` job that analyses the song, builds all five Standard difficulties, runs the Fix engine on the result and writes the finished map into `CustomLevels` (a numbered folder name when one exists already; nothing is left behind when a step fails). Song, sub name and author come from the video title, which beat-analyser uses as the project name (spaces written as underscores; it also drops brackets, so a bracketed tag cannot be recovered): "Artist - Song" gives author and song, and a bracketed part, when one survives, becomes the sub name; without a spaced dash the whole title is the song and the author is `Unknown`. saber-tooth makes no request of its own to YouTube. An analyser that still names the project by video ID gives that ID as the song. An uploaded file uses its title and artist tags (ffprobe), else its file name.
1. `GET /api/lightshow`: `{"source", "environments", "units", "learned_at"}` for the active lightshow set. `source` is `learned` when `/data/lightshow.json` exists (written by the Learn button, which then overrides the bundled set) and `bundled` otherwise; `learned_at` is the file modification time as an ISO 8601 UTC string, or null for the bundled set.
1. `POST /api/lightshow/learn`: starts a `learn` job that learns from `/levels` and writes `/data/lightshow.json`, which replaces the bundled set from then on.
1. `GET /api/vr/status`: `{"os", "runtime", "runtimes", "xr_runtime", "worn", "source"}`, the headset runtime. `source` is `agent` (the host helper at `VR_AGENT_URL`, 300 ms timeout), `local` (probed in-process on Windows or Linux) or `none`; with no helper and no probe it still answers 200 with `runtime` null and `runtimes` empty. Cached for 2 s. There is no MCP tool for it.
1. `GET /api/jobs/{id}`: `id`, `kind`, `status`, `error` and `result`.
1. BeatSaver routes, see [BeatSaver](#beatsaver).

Routes that start work answer `{"job": "<id>"}`. Poll the job until `status` is `done` or `failed`.

## Job results

1. `scan`: `{"map_id", "proposals", "analysis"}`. `proposals` is the number of proposals created, `analysis` is true when beat-analyser data was found for the map.
2. `apply`: `{"map_id", "folder"}`, the name of the folder written to `/levels`.
3. `generate`: `{"map_id", "folder", "fixes", "errors", "complete"}` of the finished map in the library: `fixes` is the number of fixes the Fix engine applied, `errors` the error findings left and `complete` is true when all five Standard difficulties exist.
4. `learn`: `{"units": N}`, the number of lightshow units indexed.
5. `bs-download`: `{"results": [{"id", "status", "reason", "folder"}]}` with `status` `installed`, `skipped` or `failed`.
6. `crop`: `{"map_id", "folder", "cropped_id", "label", "start_beat", "end_beat", "length_s"}`: the new folder, its map id, `1 min`, `2 min` or `crop MmSSs`, the chosen beats and the length in seconds.
7. A failed `apply` caused by conflicting proposals has `result` set to `{"conflict": [<proposal ids>]}` and the message in `error`.

## Errors

Errors answer `{"error": "<message>"}` with these codes.

1. 400: malformed body, missing `file`, or a URL that is not a YouTube URL.
2. 403: a `Host` outside the allowlist (any method), or a state-changing request whose `Origin` header does not match the scheme and host the client addressed (see above for proxies).
3. 404: unknown map, proposal or job. Ids that do not match their expected format are also 404.
4. 409: the map is unreadable, the proposal is already applied, or approved proposals conflict.
5. 422: a crop request whose `start_beat`, `end_beat`, `start_s` or `end_s` breaks a window rule, or a timeline that cannot be built; the message names the rule.
6. 413: the upload exceeds `MAX_UPLOAD_MB` (default 200).
7. 415: the uploaded file extension is not a supported audio type.

## BeatSaver

Search and download from BeatSaver. The server calls only `https://api.beatsaver.com` and `*.beatsaver.com` download hosts, at most 5 requests per second. Map details are cached 24 hours and query pages 10 minutes in `DATA_DIR/beatsaver.db`. Design: [spec](superpowers/specs/2026-10-27-beatsaver-integration-design.md).

1. `GET /api/beatsaver/search`: query keys `q` (200 characters), `tags` (comma list, matched as OR), `min_rating` (0 to 1), `min_upvotes` (integer, 0 to 1000000; sent to BeatSaver as `minUpVotes` and re-checked locally), `nps_min`, `nps_max` (0 to 30), `nps_scope` (`any` default or `all`), `diffs` (comma list of `Easy`, `Normal`, `Hard`, `Expert`, `ExpertPlus`), `diffs_mode` (`all` default or `any`), `ranked`, `order` (`Latest`, `Relevance`, `Rating` default, `Curated`, `Random`, `Duration`), `ascending`, `from`, `to` (`YYYY-MM-DD`), `bpm_min`, `bpm_max` (0 to 1000), `duration_min`, `duration_max` (seconds, 0 to 7200), `cursor`, `limit` (1 to 100, default 40). Difficulty and NPS filters apply to the Standard characteristic only and run locally. Answers `{"items", "cursor", "scanned", "matched"}`: `scanned` and `matched` count this response only, `cursor` is null at the end and advances even when no item matched. When BeatSaver rate limits mid-scan the response keeps what was found and adds `"partial": true` and `"retry_after"` (seconds).
   1. Item: `id`, `name`, `song`, `mapper`, `cover_url`, `preview_url` (https `*.beatsaver.com` or null), `bpm`, `duration` (seconds), `rating` (0 to 1), `upvotes`, `downvotes`, `tags`, `ranked`, `difficulties` (`[{"difficulty", "nps", "njs"}]`, Standard only), `installed`, `library_id` (library map id or null). A map is installed when a library row has its BeatSaver key or hash, or its folder starts with `<key> (`.
2. `GET /api/beatsaver/maps/{id}`: one item, 404 when unknown.
3. `GET /api/beatsaver/playlists/search`: query keys `q` (200 characters), `order` (`Latest` default, `Relevance`, `Rating`, `Curated`), `ascending`, `curated`, `verified`, `min_nps`, `max_nps` (0 to 30), `from`, `to` (`YYYY-MM-DD`), `cursor`; local filters `maps_min`, `maps_max`, `min_rating` (0 to 1), `min_upvotes`, `duration_min`, `duration_max` (seconds). Empty playlists are always excluded (`includeEmpty=false`). Answers `{"items", "cursor"}`; the cursor is the next page number and the server scans up to 5 pages to find about 20 locally matching playlists. Item: `id`, `name`, `owner`, `cover_url`, `map_count`, `mapper_count`, `duration` (total seconds), `upvotes`, `downvotes`, `rating` (0 to 1: BeatSaver `avgScore` when present, else upvotes / (upvotes + downvotes), 0 without votes), `min_nps`, `max_nps`, `created_at` (ISO string), `curated`. BeatSaver exposes no download or play count for playlists, so there is no `downloads` field.
4. `GET /api/beatsaver/playlists/{id}`: the search response over the playlist's maps (same query keys and cursor) plus `"playlist"` (the playlist item).
5. `POST /api/beatsaver/download`: body `{"ids": [...]}`, 1 to 100 BeatSaver keys (413 above 100, 400 for malformed keys). Answers `{"job"}`; the job result is `{"results": [{"id", "status", "reason", "folder"}]}`. Archives are limited to 100 MB, 400 MB expanded and 500 entries, extracted without absolute paths, `..` or symlinks, validated with the map reader, refused when they require Noodle or Mapping Extensions, and written as a new folder `<key> (<song> - <mapper>)`. Maps already in the library are skipped. The archive hash is not verified against the BeatSaver hash.
6. `POST /api/beatsaver/playlist-export`: body `{"title", "ids"}` (up to 500 ids), writes `<title>.bplist` into `PLAYLISTS_DIR` without overwriting, answers `{"path"}`. 404 when `PLAYLISTS_DIR` is not set.
7. `GET /api/beatsaver/presets`: `[{"id", "name", "filters", "seeded"}]`, `filters` using the search query keys as strings. `POST /api/beatsaver/presets` with `{"name", "filters"}` answers the preset (400 invalid, 409 duplicate name or more than 100 presets); `DELETE /api/beatsaver/presets/{id}` answers `{"deleted"}` or 404. The preset "Easy-to-Hard gems" is seeded once; a seeded row still named "Gentle full-spread hits" is renamed on open.
8. `GET /api/beatsaver/config`: `{"playlists_enabled"}`, true when `PLAYLISTS_DIR` points to an existing folder. Compose sets it from `PLAYLISTS_DIR_HOST`.

BeatSaver failures answer 404 (not found), 429 with `{"error", "retry_after"}` and a `Retry-After` header (rate limited and nothing found yet), or 502.

## URL rule

`POST /api/generate` accepts only `http` and `https` URLs whose host is exactly `youtube.com`, `www.youtube.com`, `m.youtube.com`, `music.youtube.com` or `youtu.be`. URLs with credentials, a malformed port, spaces, backslashes or non-printable characters are refused. See [ADR 0008](adr/0008-youtube-only-url-intake.md).

## Proposal states

1. `pending`: created by scan, waiting for a decision.
2. `approved`: accepted, not yet written.
3. `rejected`: declined, never written.
4. `applied`: written into the sibling folder.
5. `superseded`: an earlier approved proposal made it stale during an apply. It is never written and cannot be approved again; a still-open finding gets a new `pending` proposal whose `replaces` is this id.

## Upstream: beat-analyser

saber-tooth calls these beat-analyser routes server to server on the internal network.

1. `POST /upload`: multipart `file`.
2. `POST /download_yt`: JSON `{"url": "..."}`.
3. `GET /folders`: list project folders.
4. `GET /download/<name>`: download a project.

Project output is read from the shared volume instead; see [ADR 0005](adr/0005-beat-analyser-via-shared-volume.md).

## MCP

The same process serves a Model Context Protocol endpoint at `/mcp` (Streamable HTTP, stateless, JSON responses). It sits behind the same Host allowlist and same-origin check as the REST routes. See [ADR 0010](adr/0010-mcp-over-streamable-http-in-the-api-process.md).

Connect with `claude mcp add --transport http saber-tooth http://127.0.0.1:8100/mcp`. For another host name, add it to `SABER_ALLOWED_HOSTS`.

| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `get_proposals(map_id)`                  | Read-only. Up to 200 proposals plus `total`                                                                                                                                                                       |

| `job_status(job_id)`                     | Read-only. Job status, error and result                                                                                                                                                                           |
| `approve_proposal(id)`                   | Marks approved; idempotent; writes nothing                                                                                                                                                                        |
| `reject_proposal(id)`                    | Marks rejected; idempotent; writes nothing                                                                                                                                                                        |
| `apply_map(map_id)`                      | Starts an apply job; writes only a new folder in `CustomLevels`                                                                                                                                                   |
| `generate_from_youtube(url)`             | Starts a one-step generation job that ends in a finished map; same YouTube allowlist as `/api/generate`                                                                                                           |
